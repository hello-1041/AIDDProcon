# 水切リズム 詳細設計書

作成日: 2026-08-11

## 1. 本書の位置づけ

[基本設計書](./基本設計書.md)で定めた構成・方針をもとに、実装に着手できるレベルまで仕様を具体化する。TextAlive App APIの実際の型定義（`node_modules/textalive-app-api/dist/textalive-app-api.d.ts`）を確認した上で、利用するAPI・プロパティを確定した。数値パラメータ（閾値・距離の係数等）は初期値として設定し、実装後のプレイテストで調整することを前提とする（8章参照）。

## 2. TextAlive連携詳細

### 2.1 使用する主なAPI

| API | 概要 |
|---|---|
| `new Player({ app: { token }, mediaElement })` | Playerインスタンスの初期化 |
| `player.createFromSongUrl(songUrl)` | 楽曲URLから動画（音楽地図）データを読み込む |
| `player.addListener({ onAppReady, onVideoReady, onTimeUpdate, onPlay, onPause, onStop })` | ライフサイクルイベントの購読 |
| `player.getBeats(): IBeat[]` | 楽曲中の全ビート（拍）情報の配列（`IPlayer`直下のメソッド。`IVideo`にはビート情報はない点に注意） |
| `player.findBeat(time: number): IBeat \| null` | 指定した再生位置[ms]に重なるビート情報を取得 |
| `player.timer.position` / `onTimeUpdate(position)`の引数 | 現在の再生位置[ms] |
| `player.video.endTime: number`（`TimedObject`由来） | 楽曲の終了位置[ms]。`onTimeUpdate`内でこの値と現在位置を比較し、音楽終了を検知する（2.4節） |
| `player.requestPlay()` / `requestPause()` / `requestStop()` / `requestMediaSeek(position)` | 再生制御（いずれも`player`直下のメソッド。`player.video`には存在しない点に注意） |
| `player.video.findPhrase(time: number): IPhrase \| null` | 指定した再生位置[ms]に重なる歌詞フレーズを取得。`null`の場合、歌詞のない区間（間奏等）とみなす（4.6節） |

`IBeat`のプロパティ（`startTime`, `endTime`, `duration`, `previous`, `next`, `progress(time)`）を判定処理で使用する。再生制御系メソッドと`findBeat`/`getBeats`はいずれも`Player`クラスの型定義（`node_modules/textalive-app-api/dist/textalive-app-api.d.ts`）上で直接確認済み。

### 2.2 初期化・ライフサイクル

```ts
// src/textalive.ts
import { Player } from "textalive-app-api";

export function createPlayer(onVideoReady: () => void, onSongEnd: () => void): Player {
  const player = new Player({
    app: { token: import.meta.env.VITE_TEXTALIVE_TOKEN },
    mediaElement: document.querySelector("#media"),
  });

  player.addListener({
    onAppReady: (app) => {
      if (!app.managed) {
        // Customizer外の単独起動時は、仮の楽曲を明示的に読み込む
        player.createFromSongUrl(SAMPLE_SONG_URL, SAMPLE_SONG_OPTIONS);
      }
    },
    onVideoReady: () => {
      onVideoReady(); // ビート情報が確定した通知（game.tsへ）
    },
    // onTimeUpdateでの終了検知は2.4節を参照
  });

  return player;
}
```

- `onVideoReady`が発火した時点で`player.getBeats()`が確定し、判定処理で利用可能になる
- タイトル画面の「開始」操作をトリガーに`player.requestPlay()`を呼び、プレイ画面へ遷移する

### 2.4 音楽終了の検知

TextAlive App APIの`PlayerEventListener`には「楽曲が最後まで自然再生し終わった」ことを表す専用イベントが存在しない（`onStop`は「再生が停止されたときに呼ばれる」とだけ定義されており、本アプリのように停止操作を持たない構成では意味が曖昧になる）。そのため、音楽終了は**`onTimeUpdate`内で現在位置と楽曲終了位置（`player.video.endTime`）を比較する方式**で自前に検知する。2.2節の`addListener`に以下を追加する。

```ts
// src/textalive.ts（2.2節のcreatePlayer内、addListenerに追加）
let ended = false; // 1曲につき1回だけonSongEndを呼ぶための二重発火防止フラグ

player.addListener({
  // ...2.2節のonAppReady, onVideoReadyはそのまま
  onTimeUpdate: (position) => {
    if (!ended && position >= player.video.endTime) {
      ended = true;
      onSongEnd();
    }
  },
});
```

- `ended`フラグは、`onVideoReady`が再度発火したタイミング（リトライ時に曲の先頭から読み込み直す場合）でリセットする
- 「もう一度遊ぶ」操作時、動画データを読み込み直さずに同じ`IVideo`を使い回す場合は、`ended`を明示的にリセットする関数`resetForRetry()`を`textalive.ts`に用意する。内部では`player.requestMediaSeek(0)`で先頭に戻してから`player.requestPlay()`を呼び直す（いずれも`IPlayer`直下のメソッド。7章参照）

## 3. タイミング判定ロジック詳細

### 3.1 基準タイミングの特定

クリック時、以下の手順で「直近の基準タイミングとのズレ幅」を算出する。

```ts
function getOffsetMs(player: Player, clickTime: number): number | null {
  const beat = player.findBeat(clickTime);
  if (!beat) return null; // ビート情報の範囲外（イントロ前等）はMiss扱い

  const distToStart = Math.abs(clickTime - beat.startTime);
  const distToEnd = Math.abs(clickTime - beat.endTime);
  return Math.min(distToStart, distToEnd);
}
```

- `beat.endTime`は次のビートの`startTime`と一致するため、`startTime`/`endTime`の両方との距離を比較することで「直近の拍の境界」との差を求められる（常時受付方式）
- `clickTime`には、クリックイベント発生時点の`player.timer.position`（もしくは直近の`onTimeUpdate`で受け取った`position`）を使用する

### 3.2 判定閾値

| 判定 | ズレ幅（ms） |
|---|---|
| Just | 0 〜 50 |
| Good | 50 〜 150 |
| Miss | 150 超、またはビート情報なし |

```ts
export const JUST_THRESHOLD_MS = 50;
export const GOOD_THRESHOLD_MS = 150;

function judge(offsetMs: number | null): JudgeResult {
  if (offsetMs === null) return "miss";
  if (offsetMs <= JUST_THRESHOLD_MS) return "just";
  if (offsetMs <= GOOD_THRESHOLD_MS) return "good";
  return "miss";
}
```

閾値は初期値であり、実装後のプレイテストで調整する（8章）。

### 3.3 距離計算式

Just／Goodは常に最低距離を保証し、その範囲内でズレ幅に応じて増減する方式とする。

```ts
export const JUST_MIN_DISTANCE = 8;  // Justの最低保証距離 [m]
export const JUST_MAX_DISTANCE = 12; // ズレ0(パーフェクト)の距離 [m]
export const GOOD_MIN_DISTANCE = 3;  // Goodの最低保証距離 [m]
export const GOOD_MAX_DISTANCE = 8;  // Just境界(50ms)に近いGoodの距離 [m]

function calcDistance(judgeResult: JudgeResult, offsetMs: number): number {
  switch (judgeResult) {
    case "just": {
      const t = 1 - offsetMs / JUST_THRESHOLD_MS; // 1(ズレ0) 〜 0(50ms)
      return JUST_MIN_DISTANCE + (JUST_MAX_DISTANCE - JUST_MIN_DISTANCE) * t;
    }
    case "good": {
      const t =
        1 - (offsetMs - JUST_THRESHOLD_MS) / (GOOD_THRESHOLD_MS - JUST_THRESHOLD_MS);
      return GOOD_MIN_DISTANCE + (GOOD_MAX_DISTANCE - GOOD_MIN_DISTANCE) * t;
    }
    case "miss":
      return 0;
  }
}
```

- 上記の具体的な距離量（m表記）はゲームバランスの仮値であり、プレイテストで調整する
- Missの場合は距離を加算せず、3.4節の「石が沈む」処理へ進む

### 3.4 挑戦の終了・継続処理

```ts
function updateBest(state: GameState): void {
  state.bestDistance = Math.max(state.bestDistance, state.currentDistance);
}

function onClick(state: GameState, player: Player, clickTime: number) {
  const offset = getOffsetMs(player, clickTime);
  const result = judge(offset);
  state.lastJudge = result;

  if (result === "miss") {
    updateBest(state);
    state.currentDistance = 0; // 石が沈み、次の石がすぐ投げられる
    state.noteType = pickNextNoteType(player, clickTime); // 次の石の音符を決定（4.6節）
  } else {
    state.currentDistance += calcDistance(result, offset!);
    triggerSparkle(result); // きらめきエフェクト（4.7節）
  }
}

// 音楽終了（2.4節のonSongEnd）で呼ばれる。Missの処理と異なり、
// currentDistanceのリセットや次の音符の決定は行わず、結果確定と画面遷移のみを行う
function finishChallenge(state: GameState): void {
  updateBest(state);
  state.screen = "result";
}
```

## 4. Canvas描画設計

### 4.1 解像度・座標系

- 論理解像度は**800×600（固定）**とする
- ウィンドウサイズに応じてCSSで拡大縮小しつつ、アスペクト比を維持したレターボックス表示（余白は上下または左右に均等配置）とする
- ゲーム内の描画処理は常にこの800×600の論理座標系で行い、実際の表示倍率はCSS（`canvas`要素の`width`/`height`スタイル）側で吸収する

```ts
// src/render.ts
export const CANVAS_WIDTH = 800;
export const CANVAS_HEIGHT = 600;

export function resizeToFit(canvas: HTMLCanvasElement) {
  const scale = Math.min(
    window.innerWidth / CANVAS_WIDTH,
    window.innerHeight / CANVAS_HEIGHT
  );
  canvas.style.width = `${CANVAS_WIDTH * scale}px`;
  canvas.style.height = `${CANVAS_HEIGHT * scale}px`;
}
```

### 4.2 描画レイヤー（毎フレーム描画順）

1. 背景（空・遠景。奥行き演出として微速でスクロール）
2. 湖面（水平線より下側。4.3節のスクロール分オフセットして描画）
3. 波紋・水しぶきエフェクト
4. 石（音符。画面上のX座標は固定、Y座標は4.4節のバウンドアニメーションで上下、種類は4.6節）
5. きらめきエフェクト（Just/Good時のみ。4.7節）

### 4.3 ゲームフィールドの構図・カメラ

**視点**：横から見た側面視点。画面を水平線で上下に分け、上側を空・遠景、下側を水面とする。石は画面手前（左）から奥（右）に向かって水平方向に進む。

**石の画面上の位置**：石の画面X座標は常に固定し、実際に進んだ距離は「背景・水面のスクロール」で表現する（カメラが石に水平追従するイメージ）。石のY座標は水平線を基準に、4.4節のバウンドアニメーションで上下する。

4.5節のとおり画像素材は使わないため、「スクロール」は画像タイルの移動ではなく、**Canvasで図形描画する際の基準X座標（位相）をずらすこと**で表現する（水面の波線パターンの位相、山・雲の描画X座標など）。

```ts
// src/render.ts
export const HORIZON_Y = 350;           // 水平線のY座標（画面上側=空、下側=水面）
export const STONE_SCREEN_X = 250;      // 石を描画するX座標（画面左寄り、固定）

export const PX_PER_METER = 20;         // 距離1mあたりの水面パターンの水平移動量 [px]
export const WATER_PATTERN_WIDTH = 100; // 水面の波線パターン1周期の幅 [px]（画像ではなく、sin波の周期として使う）

export const SKY_PARALLAX_FACTOR = 0.3;  // 遠景（山・雲）は水面より遅くスクロールさせ、奥行きの遠近感を出す
export const SKY_PATTERN_WIDTH = 400;    // 遠景の図形（山・雲）を配置する周期幅 [px]
```

**スクロール量の算出**：`GameState.currentDistance`[m]を基準に、水面パターンのX方向オフセットを算出する。遠景（山・雲）は`SKY_PARALLAX_FACTOR`を掛けたより小さい量だけ動かし、水面より奥にあるように見せる（パララックス）。いずれも`% パターン幅`で無限に折り返せるため、動的な背景生成処理は不要。

```ts
function getWaterOffsetX(currentDistance: number): number {
  const scrolledPx = currentDistance * PX_PER_METER;
  return scrolledPx % WATER_PATTERN_WIDTH;
}

function getSkyOffsetX(currentDistance: number): number {
  const scrolledPx = currentDistance * PX_PER_METER * SKY_PARALLAX_FACTOR;
  return scrolledPx % SKY_PATTERN_WIDTH;
}
```

- Missで石が沈み`currentDistance`が0にリセットされると、両オフセットも0に戻る（石が湖の始点に戻ったことを視覚的に表す）
- ワイヤーフレーム（プレイ画面）は5.2節を参照

### 4.4 石の跳躍アニメーション（側面視点でのバウンド表現）

側面視点では、石が水面から跳ね上がって再び着水するまでの弧を、そのままY座標の上下運動として描画できる。

- クリック（跳躍）のたびに、石のY座標を「水平線（着水点）→一定の高さまで上昇→水平線（次の着水点）」と弧を描くように、200〜300ms程度でアニメーションさせる（イージングは放物線的な動きを想定）
- 着水の瞬間（アニメーション開始時・終了時）に、石のX座標・水平線上に波紋エフェクトを発生させる
- Miss時はこの上昇アニメーションを行わず、着水点でそのまま沈む表現（水平線からY座標が下側へ沈み込みつつ縮小・波紋が広がって消える）とする
- **アニメーション中の連続クリック**：常時受付方式（3.1節）のため、前回のバウンドアニメーション（250ms程度）が終わる前に次のクリックが来ることがある。その場合は進行中のアニメーションを中断し、その時点のY座標から新しいバウンドを即座に開始する（アニメーション状態は常に最新1件のみを保持し、キューイングはしない）。着水前でも新しいクリックの判定・距離加算は独立して行われ、アニメーション側の都合で判定自体が遅延・無視されることはない

```ts
// src/render.ts
export const BOUNCE_HEIGHT = 60;      // 跳躍時にY座標が水平線から上昇する量 [px]
export const BOUNCE_DURATION_MS = 250; // 1回の跳躍アニメーションの継続時間
```

### 4.5 ビジュアル表現方針（図形描画）

画像素材は使用せず、Canvas 2D APIの図形描画（`fillRect`／`arc`／`createLinearGradient`等）のみで全ての要素を表現する。

| 要素 | 表現方法 |
|---|---|
| 空・遠景 | 水平線から上を、上下方向のグラデーション（`createLinearGradient`）で塗りつぶす。奥行き表現として山や雲を単純な図形（三角形・楕円等）で数個配置し、水面よりゆっくり横スクロールさせる |
| 水面 | 水平線から下を、グラデーション塗りつぶし＋横方向に周期的な波線（`sin`関数で生成した細い曲線を複数本）で表現する |
| 石（音符） | 石は円形ではなく**音符**をモチーフにした図形とする。具体的な描画方法は4.6節を参照 |
| 波紋 | 着水点を中心に、半径が時間とともに広がりつつ不透明度が下がる円（`stroke`のみ、塗りつぶしなし）を1〜2個 |
| きらめき | Just/Good判定時に石の位置から放射状に飛び散る小さな星形・ダイヤ形のパーティクル。詳細は4.7節を参照 |
| 判定ポップアップ | Canvasではなく5章のとおりDOM要素・CSSで表現 |

- 具体的な配色（カラーコード）は実装時に決定する（本書では方針のみを定義し、ゲームバランスに影響しない範囲のため詳細設計のブロッカーとはしない）
- 将来的にイラスト素材（PNG/SVG）へ差し替えたくなった場合に備え、`render.ts`内の各描画処理を要素ごとの関数（`drawSky`, `drawWater`, `drawNote`, `drawRipple`, `drawSparkles`等）に分割し、差し替えが局所的な変更で済む構成とする

### 4.6 石（音符）の種類変化ロジック

石は円ではなく、**全音符／四分音符／八分音符／四分休符**の4種類の音符モチーフの中から選ばれた図形として描画する。

**種類の決定ルール**

1. ゲーム開始直後の最初の石は、常に**全音符**とする
2. Missで石が沈み、次の石が投げられる瞬間（3.4節）に、次の石の種類を以下のルールで決定する
   - その時点（Missした時刻）が**間奏中**（`player.video.findPhrase(time)`が`null`を返す＝歌詞フレーズが存在しない区間）である場合、低確率（初期値15%）で**四分休符**を選ぶ
   - 休符が選ばれなかった場合（間奏でない場合を含む）は、**四分音符**または**八分音符**を50%ずつのランダムで選ぶ
3. 休符は見た目のみの変化であり、判定・距離計算・跳躍アニメーションのロジックには一切影響しない（休符の石も通常どおりクリックして跳躍させ、スコアを稼げる）

```ts
// src/textalive.ts
export function isInterlude(player: Player, time: number): boolean {
  return player.video.findPhrase(time) === null;
}

// src/game.ts
export type NoteType = "whole" | "quarter" | "eighth" | "quarterRest";
export const NOTE_REST_PROBABILITY = 0.15;

function pickNextNoteType(player: Player, time: number): NoteType {
  if (isInterlude(player, time) && Math.random() < NOTE_REST_PROBABILITY) {
    return "quarterRest";
  }
  return Math.random() < 0.5 ? "quarter" : "eighth";
}
```

**描画方法（`render.ts`の`drawNote`）**

各音符は、符頭（ノートヘッド）・符幹（ステム）・符尾（フラグ）をCanvasの図形描画で組み合わせて表現する。

| 音符 | 構成要素 |
|---|---|
| 全音符 | 中抜きの楕円（符頭のみ、符幹なし） |
| 四分音符 | 塗りつぶした楕円（符頭）＋直線（符幹） |
| 八分音符 | 塗りつぶした楕円（符頭）＋直線（符幹）＋符幹上部に旗状のカーブ（符尾）を1本 |
| 四分休符 | ジグザグ状の曲線パス（一般的な四分休符の記号を単純化した形） |

- 跳躍アニメーション（4.4節）による拡大縮小・上下移動は、種類によらず共通のロジックを適用する（`drawNote`は種類ごとに図形を描き分けるだけで、アニメーション自体には関与しない）

### 4.7 きらめきエフェクト（跳躍時演出）

石が跳躍した際の達成感を演出するため、Just／Good判定時に石の位置からパーティクル（きらめき）を放射状に発生させる。Missの場合は発生させない。

- **Good判定**：小さめの星形パーティクルを数個（初期値5個）、石の位置から短い距離だけ飛び散らせ、`SPARKLE_DURATION_MS`（初期値450ms）かけて縮小・フェードアウトさせる控えめな演出とする
- **Just判定**：Goodより多いパーティクル数（初期値14個）を、より広い範囲・やや長い時間かけて飛び散らせ、さらに石の周囲に一瞬明るい光の輪（半透明の円を拡大させながらフェード）を加えることで、派手な演出とする

```ts
// src/render.ts
export const SPARKLE_COUNT_GOOD = 5;
export const SPARKLE_COUNT_JUST = 14;
export const SPARKLE_DURATION_MS = 450;

export function triggerSparkle(result: "just" | "good"): void; // パーティクルを生成しキューに積む
function drawSparkles(ctx: CanvasRenderingContext2D): void; // 毎フレーム、生存中のパーティクルを描画・寿命管理
```

### 4.8 音声について

クリックの跳躍・着水・きらめき等に対する効果音（SE）は**設けない**。再生される音声は、TextAlive Player（`mediaElement`）が再生する楽曲本体の音声のみとする。Web Audio API等による効果音生成、音声ファイルの追加読み込みは行わない（将来SEを追加したくなった場合のための拡張ポイントも、本バージョンでは設けない）。

## 5. 画面レイアウト詳細

### 5.1 タイトル画面

タイトルロゴ・簡単な遊び方説明・スタートボタンの3要素で構成する。アプリの正式名称は「水切リズム」だが、タイトル画面に表示するロゴ文字列は英語表記の**「MizukiRhythm」**とする。

```
+--------------------------------------------------+
|                                                    |
|                  MizukiRhythm                     |
|                                                    |
|   音楽のリズムに合わせてクリック！                    |
|   石を遠くまで飛ばしてハイスコアを狙おう              |
|                                                    |
|                [ クリックしてスタート ]              |
|                                                    |
+--------------------------------------------------+
```

- ロゴ・タイトル文字（"MizukiRhythm"）：画面上部〜中央に大きく表示
- 遊び方説明：タイトル下に2〜3行程度の短いテキスト
- スタートボタン：画面下寄り中央に配置し、クリック/タップで`player.requestPlay()`を呼びプレイ画面へ遷移する

### 5.2 プレイ画面

横から見た側面視点。水平線（`HORIZON_Y`）を境に上側が空・遠景、下側が水面。石（音符モチーフ、4.6節）は画面左寄りのX座標（`STONE_SCREEN_X`）に固定表示され、クリックのたびに水平線を基準に弧を描いて跳ね（4.4節）、背景・水面が奥（画面右から左）へスクロールすることで進行を表現する（4.3節）。Just／Good時は石の周囲にきらめきエフェクトが発生する（4.7節）。

```
+--------------------------------------------------+
| 自己ベスト: 87m                     現在: 23m       |  ← HUD（DOM要素、左上/右上）
|                                                    |
|        (山や雲などの遠景。左へゆっくりスクロール)      |
|                       Just!                       |  ← 判定ポップアップ（石の少し上、0.5秒でフェード）
|                  * ♪ *                            |  ← 音符（石）＋きらめきエフェクト
|                    ○                              |
|- - - - - - - - - - - - - - - - - - - - - - - - - -|  ← 水平線 HORIZON_Y
|~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~|  ← 水面（左へスクロール）
|~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~|
+--------------------------------------------------+
```

- HUD：画面左上に「自己ベスト」、右上に「現在の跳躍距離」を常時表示（DOM要素でCanvasにオーバーレイ）。距離は小数点以下切り捨て（`Math.floor`）の整数メートルで表示する（例：23.7m→「23m」）
- 判定ポップアップ：「Just!」「Good」「Miss」を、クリックのたびに石の少し上に一瞬表示し、約0.5秒でフェードアウトするテキスト（DOM要素＋CSSアニメーション）
- クリック操作は画面（Canvas）全体を対象とし、クリック位置は判定に影響しない（どこをクリックしても石の位置で跳躍する）

### 5.3 リザルト画面

+--------------------------------------------------+

|                   結果発表                         |
|                                                    |
|               最高記録: 128 m                      |
|                                                    |

## 7. 処理フロー（シーケンス概要）

1. `main.ts`が`createPlayer()`でPlayerを初期化し、`onVideoReady`を待つ
2. `onVideoReady`発火後、タイトル画面を表示し、ユーザーの開始操作を待つ
3. 開始操作で`player.requestPlay()`を呼び、画面を`play`に切り替える
4. Canvas上のクリックイベントで`game.handleClick()`を呼び出し、判定・距離加算・状態更新を行う（Missの場合はここで`bestDistance`更新・`currentDistance`リセット・次の音符決定まで完結する）
5. `requestAnimationFrame`ループが毎フレーム`render.drawFrame()`と`ui.updateHud()`を呼び、状態を画面に反映する
6. `textalive.createPlayer()`内部で検知した音楽終了（2.4節）で`onSongEnd`コールバックが呼ばれ、`game.finishChallenge()`を実行して`bestDistance`を確定し、リザルト画面へ遷移する
7. リザルト画面で「もう一度遊ぶ」→ `game.createInitialState()`で状態を初期化＋`textalive.resetForRetry(player)`で楽曲を先頭から再生し、3へ。「タイトルに戻る」→ タイトル画面へ（楽曲の再生は停止する）
