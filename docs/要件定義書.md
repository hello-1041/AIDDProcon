# 水切リズム 要件定義書

作成日: 2026-08-11

## 1. 概要

### 1.1 アプリ名
正式名称：「水切リズム」（ゲーム内タイトル画面での表示名は英語表記「MizukiRhythm」とする）

### 1.2 目的
[TextAlive App API](https://developer.textalive.jp/) を利用し、再生中の楽曲のリズムに合わせて画面をクリックすることで石を湖面に跳ねさせ、遠くまで飛ばすことを競うWebブラウザ向けリズムゲームを開発する。

### 1.3 コンセプト
- 川遊びの一つである「水切り」をモチーフにした、音楽同期型のリズムゲーム
- 舞台は川ではなく**湖**（波が穏やかで、石が跳ねる演出に適した設定）
- TextAlive App APIから取得できる楽曲のタイミング情報（拍・ビート等）を基準に、プレイヤーのクリックタイミングを判定する
- タイミングが良いほど石が遠くまで跳ね、ズレが大きいと石が沈んでしまう、というシンプルな一発ルールで、音楽に乗る楽しさとハイスコア狙いの挑戦性を両立する

## 2. 対象ユーザー・想定プレイ環境

- 主な対象：PCブラウザでプレイするユーザー（マウスクリック操作を基本とする）
- 入力デバイス：マウスクリックを基本とし、将来的にはタップ操作（スマートフォン・タブレット）にも対応できるよう、入力処理は「クリック／タップ共通のポインターイベント」として設計することを想定する（本格対応は本要件のスコープ外、詳細は9章参照）
- 動作環境：モダンブラウザ（Chrome, Edge等の最新版を想定。詳細な対応範囲は7章参照）

## 3. 用語定義

| 用語 | 説明 |
|---|---|
| 跳躍（スキップ） | プレイヤーのクリックにより石が湖面を1回跳ねること |
| 挑戦（1投） | 石を投げてから、沈む（挑戦終了）までの一連の跳躍の連なり |
| 跳躍距離 | 1回の挑戦において、石が跳ね始めてから現在までに進んだ累積距離 |
| 自己ベスト（最高記録） | プレイ開始から現在までの挑戦の中で記録された、跳躍距離の最大値。最終スコアとなる |
| タイミング判定 | TextAliveから取得する拍等のタイミング情報と、実際のクリック時刻とのズレを評価する処理 |
| ズレ幅 | 基準タイミングと実際のクリック時刻との差（時間） |

## 4. ゲームフロー

1. **タイトル画面**：ゲームタイトルと開始操作を表示
2. **プレイ開始**：楽曲の再生を開始し、TextAlive App APIからタイミング情報の取得を開始する
3. **プレイ中**：
   - 石が湖面に投げられ、挑戦（1投）が始まる
   - プレイヤーが画面をクリックするたびに、直近の基準タイミングとのズレ幅を判定し、跳躍距離を加算する（詳細は5.3）
   - ズレが一定以上大きい（ミス判定）場合、石が沈み、その挑戦は終了する
     - 終了時点までの跳躍距離が、これまでの自己ベストを上回っていれば自己ベストを更新する
     - 直後に新しい石が湖面に投げられ、次の挑戦が即座に始まる（音楽が終わるまでこのサイクルを繰り返す）
4. **音楽終了**：楽曲の再生が終了した時点で、進行中の挑戦を終了し、その時点の自己ベストを最終スコアとして確定する
5. **リザルト画面**：最終スコア（自己ベスト＝最大跳躍距離）を表示する

```
[タイトル画面] → [楽曲再生開始]
                     ↓
        ┌─→ [石を投げる（挑戦開始）]
        │        ↓
        │   [クリックで跳躍／距離加算] ←─┐
        │        ↓                    │
        │   ズレ小 ─────────────────┘（挑戦継続）
        │        ↓ ズレ大（ミス）
        │   [石が沈む／自己ベスト更新] 
        └────── 音楽が続いていれば次の石へ
                     ↓（音楽終了）
              [リザルト画面：自己ベストを表示]
```

## 5. 機能要件

### 5.1 TextAlive連携
- `textalive-app-api` の `Player` を用いて楽曲を再生する
- 楽曲は**固定の1曲**を使用する（曲名・楽曲URLは別途選定・確定する。詳細は9章の後続フェーズで複数曲対応を検討）
- TextAliveから取得できるタイミング情報（ビート／拍情報等、具体的にどの情報を基準タイミングとするかは詳細設計フェーズで確定：TBD）をもとに、判定の基準タイミングを算出する

### 5.2 操作仕様
- プレイヤーは画面をマウスクリックすることで、現在の石を1回跳躍させる
- クリックのたびに、直近の基準タイミングとのズレ幅を判定する

### 5.3 タイミング判定・スコアロジック
- **判定基準**：クリック時刻と基準タイミングとのズレ幅に応じて複数段階の判定（例：Just／Good／Missなど）を設ける。具体的な閾値は詳細設計フェーズで決定する（TBD）
- **跳躍距離の算出**：ズレ幅が小さいほど、その回の跳躍で進む距離が大きくなる。ズレ幅と距離の具体的な計算式は詳細設計フェーズで決定する（TBD）が、「ジャストタイミングに近いほど有利」という方針を基本とする
- **ミス（石が沈む）条件**：ズレ幅が一定の閾値を超えた場合、石が沈み、その挑戦（1投）は終了する。閾値は詳細設計フェーズで決定する（TBD）
- **自己ベストの更新**：挑戦が終了する（石が沈む、または音楽が終了する）たびに、その挑戦で記録した跳躍距離が既存の自己ベストを上回っていれば更新する
- **次の挑戦への継続**：石が沈んだ直後、自動的に新しい石が湖面に投げられ、次の挑戦が始まる。プレイヤー側の操作（リトライボタン等）は不要とし、音楽が終わるまでゲームは継続する

### 5.4 スコア表示
- **プレイ中HUD**：現在の挑戦の跳躍距離、および現在の自己ベストをリアルタイムに表示する
- **リザルト画面**：音楽終了時点の自己ベストを最終スコアとして表示する

## 6. 画面一覧

| 画面 | 役割・主な要素 |
|---|---|
| タイトル画面 | アプリ名（「MizukiRhythm」）表示、ゲーム開始操作 |
| プレイ画面 | 湖・石・波紋等のCanvas描画、現在の跳躍距離／自己ベストのHUD表示 |
| リザルト画面 | 最終スコア（自己ベスト）の表示、リトライ操作（タイトルに戻る／再プレイ等、詳細はTBD） |

## 7. 非機能要件

- **対応ブラウザ**：モダンブラウザ（Chrome, Edge等）の最新版を想定。詳細な対応バージョンはTBD
- **パフォーマンス**：Canvas描画による水面・石のアニメーションが滑らかに（目安として60fps程度を想定）表示されること
- **動作確認**：TextAlive App Customizer（HTTPS環境が必要）経由での動作確認を想定し、`temp/textalive-app-api-setup-plan.md` に記載のngrok等によるHTTPS化の手順を利用する
- **レスポンシブ対応**：本フェーズではPCブラウザでの表示を優先し、画面サイズ対応の詳細はTBD（9章参照）

## 8. 技術構成

- フレームワーク：Vite + TypeScript（Vanilla構成）
- TextAlive連携：`textalive-app-api`（npmパッケージ）
- 描画：Canvas 2D API（追加の描画ライブラリは使用せず自前実装）
- 環境構築の詳細手順：`temp/textalive-app-api-setup-plan.md` を参照

## 9. 今後の検討事項（本要件のスコープ外・後続フェーズ）

- **複数曲対応**：後続フェーズで、複数の楽曲から選択できる曲選択画面を追加する
- **モバイル／タップ操作の正式対応**：スマートフォン・タブレットでのタップ操作への正式対応（UIレイアウト含む）
- **ランキング・スコア共有機能**：スコアの保存・共有・ランキング機能の要否
- **演出面の詳細**：グラフィック・エフェクト（波紋、水しぶき、石の見た目等）の具体的なデザイン
- **判定閾値・距離計算式の確定**：5.3節でTBDとした具体的な数値・計算式
